# 正交场景设计:派生节点每档独立 1m 选择(per-tier contextWindow)

## 任务背景

派生节点编辑器的"会话档位(200K/1M)"目前是**整个配置一个 radio**,4 个档位(main/haiku/sonnet/opus)共用一个 `sessionContext1m: boolean`。用户要求:**每个档位各自独立选 200K/1M**,别名 key 按各档选择独立带 `[1m]` 后缀。选 200K 的档位别名不带 `[1m]`,选 1M 的带。

## 数据结构变更

- `types.ts`:`sessionContext1m?: boolean` → `sessionContext1m?: { main?: boolean; haiku?: boolean; sonnet?: boolean; opus?: boolean }`(每档一布尔,语义同原:true=1M/带 [1m])。
- **向后兼容老派生节点**:老数据 `sessionContext1m: true/false`(布尔)需迁移。读取时若发现是布尔,展开成四档同值(`true` → `{main:true,haiku:true,sonnet:true,opus:true}`,`false` → 全 false)。`undefined` 保持 undefined(创建时填默认)。

## 函数变更

### `aliasName(tier, index, with1m)` — 不改签名
已支持 per-call `with1m`。调用方按各档的 1m 选择传入即可。

### `buildAliasEnv(derivedIndex, opts)` — 改 opts
- 现:`{ with1m?: boolean }` 统一四档。
- 改:`{ sessionContext1m?: PerTier1m }`(每档对象)。buildAliasEnv 内部按各档的 1m 选择调 `aliasName(tier, idx, perTier[tier])`。
- 向后兼容:若传 `{ with1m: boolean }`(老调用)仍工作?claudeLauncher 是唯一调用方,会同步改,故直接改签名,不留旧兼容。但为防其他地方残留,opts 同时认 `with1m`(布尔,展开四档)和 `sessionContext1m`(对象),后者优先。

### `inheritSessionContext1m(parentContent)` — 改返回
- 现:返 boolean(父 ANTHROPIC_MODEL 带 [1m] → true)。
- 改:返 `PerTier1m`(四档同值,均 = 父是否带 [1m])。语义:四档默认都从父继承(用户已确认)。
- 调用方 webviewEditor 创建派生时用它填初值。

### `computeAliasSyncActions` — 不变
别名 key 不带 [1m](约束 3:rewriteModel 剥后缀查表),`aliasName(tier, idx)` 仍用 `with1m=false`。映射 key 不受 per-档 1m 影响。

## 正交维度

### D1: per-档 1m 数据结构维度
- D1a 四档同值(继承场景)
- D1b 各档不同值(用户分别设)
- D1c 部分档 undefined(老数据迁移后可能某档缺)→ 视为 false(200K)
- D1d 全 undefined(新建未填)→ 用继承初值

### D2: 别名后缀维度(per-档)
- D2a 档选 1M → 该档别名带 [1m]
- D2b 档选 200K → 该档别名不带 [1m]
- D2c 档 undefined → 默认 200K(不带)

### D3: 向后兼容维度
- D3a 老数据 `sessionContext1m: true`(布尔)→ 迁移成四档 true
- D3b 老数据 `sessionContext1m: false`(布尔)→ 迁移成四档 false
- D3c 老数据 `sessionContext1m: undefined` → 保持 undefined
- D3d 新数据 `sessionContext1m: {main:true,...}` → 原样用

### D4: 继承维度
- D4a 父 ANTHROPIC_MODEL 带 [1m] → 四档默认 true
- D4b 父不带 / 父无 model / content 无效 → 四档默认 false
- D4c 父带 [2m](CLI 不认)→ false

### D5: buildAliasEnv 维度
- D5a 四档各按自身 1m → 各 env 别名后缀独立
- D5b opts.sessionContext1m 为对象 → 各档取自身
- D5c opts.with1m(布尔,兼容)→ 四档同值
- D5d opts 都缺 → 四档 false(200K)

### D6: webview UI 维度
- D6a 每档映射行各有 200K/1M 选择
- D6b 改某档 1m → setCtx1m 带 tier,只更新该档
- D6c 全局 radio 去掉
- D6d 别名预览按各档 1m 显示后缀

## 高风险边界(必须有 case)

1. **状态转换**:档 1m 改动 → 该档别名后缀变 → 需重启 CLI;迁移老数据不丢档位信息
2. **异常路径**:sessionContext1m 既非布尔也非对象(脏数据 string/null/number)→ 兜底;buildAliasEnv 收到非法对象
3. **类型安全**:per-tier 对象的 value 非布尔(脏数据)→ 视为 false;undefined 档 → false
4. **空/初始**:全新派生节点 sessionContext1m=undefined → 用继承初值填
5. **幂等**:同输入同输出;迁移重复读不变形
6. **边界**:只有 main 有值其他 undefined;某档 true 其他 false(混合)
